# AutoPlaceMiner 开发说明

面向开发与构建，不包含在游戏的 mod 介绍中。

## 构建

需要 .NET SDK、BepInEx 5.4.x 和游戏 `Assembly-CSharp.dll`。项目引用路径在 `..\DSPMods.Shared\DSPMods.Shared.props` 中配置。

```powershell
dotnet build .\AutoPlaceMiner\AutoPlaceMiner.csproj -c Release
```

构建后会自动复制到 r2modman 的 `Default` profile（可在 csproj 的 `DeployPluginDir` 中修改）。

## 实现要点

- 仅对 `PrefabDesc.isVeinCollector` 的大型采矿机生效。
- 根据鼠标附近矿脉群计算中心，把目标矿点投影到局部 UV 平面。先用 90 个角度（4°）做 12.5×15.5 矩形滑动扫描；粗扫有候选时先走原生校验，只有粗扫无候选或候选全部校验失败，才退回 0.5° 精扫。
- 找到建造范围内的满覆盖候选时收集多个满覆盖候选，优先做几何碰撞预筛（底座 Box 对矿脉/建筑 ColliderData），再对通过预筛的候选做原生建造校验；满覆盖候选存在时不会降级到低覆盖候选。
- 每个角度最多评估 12 个中心；某个角度一旦达到满覆盖，立即停止该角度的次优中心评估，但仍继续其它角度以取得不同朝向的满覆盖候选。
- 几何候选全部被原生规则拒绝且没有满覆盖候选时，退回原有的位置网格 + 角度精扫作为兜底；满覆盖候选仅因矿脉碰撞失败时也允许回退低覆盖位置。几何最优解超出建造范围或满覆盖候选因其它原因失败时直接提示。
- 用原生 `BuildTool_Click.CheckBuildConditions` 做最终合法性校验。
- 校验期间临时隐藏当前手持建筑的预览模型，避免把玩家自己的预览当成碰撞体。
- 通过后调用原生 `CreatePrebuilds` 放置。
- 液体/坑洼矿脉：先做普通原生校验；没有更好的陆地位置时，对水面、熔岩、硫酸或原生报 `NeedGround` 的低洼坑地候选铺设地基（尺寸按建筑占地计算），再重新跑原生校验和放置。地基逻辑与 AutoConnectPower 一致，会消耗地基物品和沙土；普通高地/陡坡不整平。
- 原生 `CheckBuildConditions` 使用地形高度的落点（与手动预览一致），真正创建预建造时再放到海平面 `realRadius + 0.2`，让游戏下挖地形；这样高地不会因为校验位置过低被误判成 `NeedGround`。
- 完全掩埋矿脉：搜索前按 UXAssist 的方式把矿脉、碰撞体和模型恢复到 `QueryModifiedHeight` 地表，并用 `MinerPlacementGeometry` 检查建筑碰撞，恢复后重新统计矿脉群。
- `Alt+Q` 批量模式与单个 `Q` 共用 `TryPlaceGroup`：每个矿脉群都执行恢复掩埋、重新统计、几何搜索、满覆盖碰撞回退网格、自动地基和原生放置/虚影判定；已有矿机/预建造的群跳过。批量候选先走原生校验，`Place` 内部按原始建造范围和覆盖数决定实际建造还是白色虚影，不在候选阶段按范围过滤。范围外临时放宽 `player.mecha.buildArea` 通过原生校验，再按 AutoConnectPower 的方式直接 `AddPrebuildDataWithComponents` 生成白色虚影，结束后恢复建造范围。几何搜索中若所有满覆盖中心都被矿脉碰撞排除，会保留低覆盖候选供批量虚影回退；批量虚影在生成前也会用 `buildColliders` 做一次底座碰撞检查，避免白色虚影穿模。

## 性能

- 每个角度先做固定矩形滑动扫描，命中满覆盖后不再评估该角度的次优中心。
- 满覆盖候选在几何搜索阶段就按 `buildColliders` 对矿脉/建筑做碰撞筛选：底座会压矿脉的中心直接排除，不再只检查前几个中心；只有没有任何满覆盖中心可行时才回退网格搜索。几何模型对 Box/Sphere/Capsule 做 SAT/距离判断，并跳过无效 `ColliderData`；`VerboseLog` 可看具体碰撞对象。
- 覆盖判断使用预归一化的矿点坐标和点积，并固定在 200m 投影面计算；每个角度最多评估 12 个中心，找到第一个几何合法的满覆盖候选后转向下一个角度。所有角度扫描完后最多选取 48 个不同朝向的候选，避免候选全部集中在矿脉同一侧。粗扫 90 角度有候选就先校验；只有无候选或全部校验失败才做 720 角度精扫。候选集合只由矿脉群几何生成，鼠标仅用于同覆盖数排序；目标矿脉群仍由鼠标位置决定。中心按覆盖数、U、V 固定排序，避免同分顺序变化影响候选数。
- 日志会显示几何搜索与原生校验耗时；开启 `VerboseLog` 后可看候选统计。

## 日志排查

- `目标矿脉群 ... 共 N 条 ... 候选最大覆盖 X/N`：搜索阶段。
- `当前预览条件 ... 隐藏预览模型 ...`：原生校验前的状态。
- `所有候选位置均被原生规则拒绝：...`：查看具体拒绝原因（Collide、OutOfReach、NeedResource 等）。
- `已放置大型采矿机：... 矿脉群共 N 条，本机覆盖当前群 X 条 ...`：最终结果。
