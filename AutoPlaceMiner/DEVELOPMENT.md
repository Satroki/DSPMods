# AutoPlaceMiner 开发说明

面向开发与构建，不包含在游戏的 mod 介绍中。

## 构建

需要 .NET SDK、BepInEx 5.4.x 和游戏 `Assembly-CSharp.dll`。项目引用路径在 `..\DSPMods.Shared\DSPMods.Shared.props` 中配置。

```powershell
dotnet build .\AutoPlaceMiner\AutoPlaceMiner.csproj -c Release
```

构建后会自动复制到 r2modman 的 `Default` profile（可在 csproj 的 `DeployPluginDir` 中修改）。

## 实现要点

- 仅对 `PrefabDesc.isVeinCollector` 的大型采矿机生效。
- 根据鼠标附近矿脉群计算中心，把目标矿点投影到局部 UV 平面；每个 0.5° 角度用 12.5×15.5 矩形的滑动扫描直接求最大覆盖中心，再对每个角度的前几个中心做原生校验。
- 找到建造范围内的满覆盖候选时收集多个满覆盖候选，优先做几何碰撞预筛（底座 Box 对矿脉/建筑 ColliderData），再对通过预筛的候选做原生建造校验；满覆盖候选存在时不会降级到低覆盖候选。
- 每个角度最多评估 6 个中心；某个角度一旦达到满覆盖，立即停止该角度的次优中心评估，但仍继续其它角度以取得不同朝向的满覆盖候选。
- 几何候选全部被原生规则拒绝且没有满覆盖候选时，退回原有的位置网格 + 角度精扫作为兜底；几何最优解超出建造范围或满覆盖候选全部失败时直接提示，不回退。
- 用原生 `BuildTool_Click.CheckBuildConditions` 做最终合法性校验。
- 校验期间临时隐藏当前手持建筑的预览模型，避免把玩家自己的预览当成碰撞体。
- 通过后调用原生 `CreatePrebuilds` 放置。
- 水中矿脉：先做普通原生校验；没有更好的陆地位置时，对高覆盖水面候选铺设地基（尺寸按建筑占地计算），再重新跑原生校验和放置。地基逻辑与 AutoConnectPower 一致，会消耗地基物品和沙土。
- 完全掩埋矿脉：搜索前按 UXAssist 的方式把矿脉、碰撞体和模型恢复到 `QueryModifiedHeight` 地表，并用 `MinerPlacementGeometry` 检查建筑碰撞，恢复后重新统计矿脉群。
- `Alt+Q` 批量模式：以当前矿脉群类型为准，遍历当前星球所有同类矿脉群（包含当前群）；已有矿机/预建造的群跳过。范围内正常校验放置；范围外临时放宽 `player.mecha.buildArea` 通过原生校验，再按 AutoConnectPower 的方式直接 `AddPrebuildDataWithComponents` 生成白色虚影，结束后恢复建造范围。

## 性能

- 每个角度先做固定矩形滑动扫描，命中满覆盖后不再评估该角度的次优中心。
- 满覆盖候选在几何搜索阶段就按 `buildColliders` 对矿脉/建筑做碰撞筛选：同角度所有满覆盖中心都会尝试，底座会压矿脉的中心直接排除，不再只检查前几个中心；只有没有任何满覆盖中心可行时才回退网格搜索。几何模型对 Box/Sphere/Capsule 做 SAT/距离判断，并跳过无效 `ColliderData`；`VerboseLog` 可看具体碰撞对象。
- 覆盖判断使用预归一化的矿点坐标和点积，并固定在 200m 投影面计算；每个角度保留最多 12 个中心，满覆盖候选不再只取第一个。候选集合只由矿脉群几何生成，鼠标仅用于同覆盖数排序；目标矿脉群仍由鼠标位置决定。中心按覆盖数、U、V 固定排序，避免同分顺序变化影响候选数；简单矿脉累计到 32 个几何合法的满覆盖候选后停止角度扫描。
- 日志会显示几何搜索与原生校验耗时；开启 `VerboseLog` 后可看候选统计。

## 日志排查

- `目标矿脉群 ... 共 N 条 ... 候选最大覆盖 X/N`：搜索阶段。
- `当前预览条件 ... 隐藏预览模型 ...`：原生校验前的状态。
- `所有候选位置均被原生规则拒绝：...`：查看具体拒绝原因（Collide、OutOfReach、NeedResource 等）。
- `已放置大型采矿机：... 矿脉群共 N 条，本机覆盖当前群 X 条 ...`：最终结果。
